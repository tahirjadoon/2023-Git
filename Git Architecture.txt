main
└── integration   (🔵 reset each release)
    └── feature/qa01
        └── feature/some-project
		
1. feature/some-project → feature/qa01
git switch feature/env-a
git merge --squash feature/some-project  [or pull request]
git commit -m "Promote some-project to env-a"

2. feature/env-a → integration [via the promotion/wrapper branch]
git switch integration
git merge --no-ff feature/env-a -m "Promote env-a to integration"

	Why?
	• 	You want a traceable promotion event
	• 	You want to know exactly what env‑a delivered
	• 	You do NOT want to rewrite history here
	• 	Multiple teams will be merging into integration
	This keeps integration auditable.
	
3. integration → main [via the promotion/wrapper branch]
git switch main
git merge --no-ff integration -m "Release from integration"
